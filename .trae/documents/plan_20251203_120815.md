# 解决方案

## 问题分析
1. **当前配置**：
   - `docker-compose.yml` 使用硬编码镜像地址 `docker.io/aspnmy/curd_apirust:v0.1.0`
   - `docker-build.yml` 工作流构建镜像并推送到 GitHub Container Registry (ghcr.io)
   - 工作流当前监控所有文件变更，包括 `docker-compose.yml`

2. **用户需求**：
   - 将 `docker-compose.yml` 中的镜像地址修改为工作流构建后的最新tag
   - 确保 `docker-compose.yml` 不在工作流监控范围内
   - 实现构建后自动更新镜像地址的效果

## 解决方案

### 1. 修改 GitHub Actions 工作流 (`docker-build.yml`)

#### 1.1 添加 `paths-ignore` 配置
在工作流的 `push` 和 `pull_request` 事件中添加 `paths-ignore`，忽略 `docker-compose.yml` 文件的变更：

```yaml
on:
  push:
    branches: [ main, dev_rust ]
    paths-ignore:
      - 'docker-compose.yml'
  pull_request:
    branches: [ main, dev_rust ]
    paths-ignore:
      - 'docker-compose.yml'
```

#### 1.2 优化标签生成
确保工作流生成稳定的分支标签，用于 `docker-compose.yml` 引用：

```yaml
tags: |
  type=ref,event=branch
  type=ref,event=pr
  type=sha,format=short
  type=raw,value=latest,enable={{is_default_branch}}  # 仅默认分支推latest标签
```

### 2. 更新 `docker-compose.yml`

#### 2.1 修改镜像地址
将硬编码的 `docker.io/aspnmy/curd_apirust:v0.1.0` 替换为工作流构建的最新标签：

```yaml
# 生产环境（默认分支）
image: ghcr.io/aspnmy/curd_apiRust:latest

# 或开发环境
image: ghcr.io/aspnmy/curd_apiRust:dev_rust
```

#### 2.2 保持配置文件结构
保留其他配置不变，确保服务正常运行。

## 实现效果
1. **自动更新**：工作流每次构建都会更新分支标签或 `latest` 标签
2. **避免循环触发**：`docker-compose.yml` 变更不会触发工作流
3. **版本控制**：使用分支标签或 `latest` 标签确保获取最新构建
4. **简化部署**：`docker-compose up -d` 会自动拉取最新镜像

## 关键技术点
- **GitHub Actions 路径过滤**：使用 `paths-ignore` 避免不必要的构建
- **Docker 标签策略**：结合分支标签和 `latest` 标签实现灵活部署
- **镜像拉取策略**：Docker Compose 会自动检查并拉取最新标签的镜像
- **工作流优化**：确保工作流仅在必要时运行，提高构建效率

## 注意事项
- 确保 GitHub 仓库名称正确映射到 `ghcr.io/aspnmy/curd_apiRust`
- 根据部署环境选择合适的标签（`latest` 或分支标签）
- 首次部署前需要手动拉取镜像：`docker pull ghcr.io/aspnmy/curd_apiRust:latest`

通过以上修改，可以实现 `docker-compose.yml` 使用工作流构建的最新镜像，同时避免 `docker-compose.yml` 变更触发工作流的循环问题。
