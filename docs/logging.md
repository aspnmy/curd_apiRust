# 日志记录配置文档

## 1. 概述

本项目使用 `tracing` 框架进行日志记录，支持控制台输出和文件输出，并可通过环境变量进行配置。

## 2. 日志配置参数

| 环境变量名 | 默认值 | 描述 |
|------------|--------|------|
| DEBUG | false | 是否启用调试模式，调试模式下日志级别为 debug |
| LOG_PATH | ./logs | 日志文件保存路径 |

## 3. 日志级别

| 级别 | 描述 |
|------|------|
| debug | 调试信息，包括详细的请求和响应内容 |
| info | 普通信息，包括请求处理流程和重要操作 |
| warn | 警告信息，包括潜在问题和非致命错误 |
| error | 错误信息，包括严重错误和异常情况 |

## 4. 日志格式

日志格式包含以下信息：
- 时间戳（精确到毫秒）
- 日志级别
- 模块名称
- 日志消息
- 可选的结构化数据

## 5. 日志文件

日志文件保存在 `LOG_PATH` 配置的目录下，文件名为 `app.log`。日志会追加到文件末尾，不会自动滚动。

## 6. API 端点

### 6.1 GET /api/logs

获取日志内容，仅在调试模式下可用。

#### 请求参数

无

#### 响应格式

```json
{
  "logs": "日志内容字符串"
}
```

#### 状态码

| 状态码 | 描述 |
|--------|------|
| 200 | 成功获取日志 |
| 403 | 非调试模式下访问被拒绝 |
| 500 | 读取日志文件失败 |

## 7. 配置示例

### 7.1 调试模式配置

```dotenv
DEBUG=true
LOG_PATH=/var/logs/crud-api
```

### 7.2 生产模式配置

```dotenv
DEBUG=false
LOG_PATH=/var/logs/crud-api
```

## 8. Docker 配置

在 Docker 容器中，可以通过环境变量或 docker-compose.yml 文件配置日志参数。

### 8.1 docker-compose.yml 示例

```yaml
services:
  crud-api:
    image: crud-api:latest
    environment:
      - DEBUG=true
      - LOG_PATH=/var/logs/crud-api
    volumes:
      - ./logs:/var/logs/crud-api
```

## 9. 日志记录内容

系统会记录以下内容：
- 服务启动和关闭信息
- 配置加载和验证信息
- 数据库连接和迁移信息
- API 请求和响应信息
- 错误和异常信息
- 服务健康状态信息

## 10. 日志最佳实践

1. 在开发环境中启用调试模式，以便查看详细日志
2. 在生产环境中禁用调试模式，仅记录必要的信息
3. 定期清理日志文件，避免磁盘空间耗尽
4. 对日志文件设置适当的权限，防止未授权访问
5. 使用日志聚合工具（如 ELK Stack、Prometheus + Grafana）集中管理日志

## 11. 常见问题

### 11.1 日志文件无法创建

检查 `LOG_PATH` 目录是否存在，以及应用程序是否有写权限。

### 11.2 日志级别不生效

确保 `DEBUG` 环境变量设置正确，且日志初始化代码执行成功。

### 11.3 /api/logs 端点返回 403

确保 `DEBUG` 环境变量设置为 `true`。
